## 一、背景与决策链

**起点问题**：批次十六~二十的绑定面 = `bridge.rs` 扁平原生函数（受 RP 原生
函数限制：7 参上限、tuple 平铺消费、无默认值/kwargs）+ `pygame_shim.py`
（纯 Python，组装 pygame 包 + 承担全部参数整形）。shim 里约 80% 是
"补偿 Rust 面签名残缺"的转发层——转发体量 ≈ Rust 面的残缺量。

**用户决策（两条设计原则）**：
1. **参数形式在 Rust 侧固定成简单形态**——Python 的解包/可变长/默认值
   等复杂参数问题在原生面一次性整形定约，签名即文档，开发者顺手，
   避免 C++ 式复杂难懂接口，长期减少 Rust 开发量；
2. **能力住 Rust，长相也住 Rust**——Rust 实现能力，Python 面（含组装）
   不应有第二份逻辑；纯转发层没有存在意义。

**两批推进**：
- **批次 A（签名整形）**：draw 族改 `#[derive(FromArgs)]` 结构体收参，
  序列整形下沉 `args`——shim 转发归零，类型资产沉淀；
- **批次 B（原生模块）**：`#[pymodule]` 原生注册 pygame 模块树 +
  Screen/Session/Event pyclass，`pygame_shim.py` 删除退役。

## 二、总体架构

### 2.1 分层链（自上而下，单向）

```
用户 Python 脚本（标准 import pygame，无任何特殊写法）
        │ import 先查 sys.modules["pygame"] ← install_pygame() 注入
        ▼
┌─ native_pygame.rs（Python 面，批次 B 新建）────────────────┐
│  #[pymodule] pygame                                        │
│   ├ 常量：QUIT / KEYDOWN / … / K_ESCAPE     （pyattr）     │
│   ├ Color / init / quit                     （pyfunction） │
│   ├ display：set_mode → Screen · flip                      │
│   ├ event：get() → [Event]（排空 bridge 事件队列）             │
│   ├ time：get_ticks · delay                                │
│   └ pyclass：Screen（render→Session·fill）                 │
│              Session（__enter__/__exit__ + 5 绘制方法）    │
│              Event（type/key/x/y/button getset + repr）    │
└─────────────┬──────────────────────────────────────────────┘
              │ 直调复用（pub(crate)，无转发层）
              ▼
┌─ bridge.rs + args.rs（能力/引擎侧）────────────────────────┐
│  session_begin/end（RenderPass 存 thread-local 会话）      │
│  drain_events（事件队列）· devlog 诊断计数                 │
│  sf_draw_*（FromArgs 结构体收参）+ SfColor/Rect/Point/Points│
│  旧扁平别名 fill/rect/flip/quit_requested（旧脚本沿用）    │
└─────────────┬──────────────────────────────────────────────┘
              ▼
   starfish::pygame 兼容层 → starfish::base（wgpu + starfish-window）
```

### 2.2 宿主壳装配时序（examples 同构）

```rust
display::set_mode((800, 600)).await   // ① GPU 真身先行（Android 横屏坑：启动即 set_mode）
let interp = rpy::new_interpreter();  // ② 解释器（init_hook 只抬 recursion_limit）
interp.enter(|vm| {                   // ③ enter 内（essential init 完成后）：
    rpy::bridge::register(vm, &scope); //   bridge 全局（旧别名 + 探针面）
    rpy::install_pygame(vm);          //    原生 pygame 模块注入 sys.modules
    /* 编译脚本 → 取 game 生成器 */    //    脚本标准 import pygame
});
loop { pump → __next__ → next_frame } // ④ 生成器门主循环（yield = 帧边界）
```

**生命周期红线（批次 B 实测钉死）**：`install_pygame` **必须**在
`interp.enter` 内、essential init 完成后调用。放进 init_hook（解释器
初始化深处、importlib 引导未完）动模块机制 → **无限递归爆栈**（连
`import sys` 都炸，STATUS_STACK_OVERFLOW，文件日志二分定位到
`sys.modules` fetch 行）。

## 四、批次 A：签名整形

### 4.1 机制原理（为什么可行）

RP 原生函数的 7 参上限**不是 trait 限制，是宏重复展开上限**
（`function/builtin.rs:205-220` 只 impl 到 7 前置参数）。而参数绑定走
`FuncArgs::bind_for` → 每个形参调 `FromArgs::from_args`——**FromArgs
结构体算 1 个形参，字段各自消费位置参数/kwargs**。因此：

```rust
#[derive(FromArgs)]
struct DrawRectArgs {
    #[pyarg(any)] color: SfColor,          // any = 位置或关键字
    #[pyarg(any)] rect: SfRect,
    #[pyarg(any, optional)] width: Option<i32>,  // 缺省 → None → 0 填充
}

fn sf_draw_rect(args: DrawRectArgs, vm: &VirtualMachine) -> PyResult<()>
```

- `Fn(Args, &VirtualMachine)` 仅 2 前置参——彻底绕开 7 参上限；
- `#[pyarg(any, optional)]` = 缺省值；`named` = 仅关键字；
- kwargs 未被消费 → 自动报 unexpected keyword argument（自由而不混乱）。

### 4.2 args：序列整形的单一实现

| 类型 | 收（Python 形态） | 出（Rust 定约） |
|---|---|---|
| `SfColor` | `(r,g,b)` / `(r,g,b,a)` | `[u8; 4]`（缺 alpha 补 255；分量 0..=255 校验，越界中文 TypeError） |
| `SfRect` | `(x, y, w, h)` 序列 | `{x, y, w, h}: i32` |
| `SfPoint` | `(x, y)` 序列 | `(i32, i32)` |
| `SfPoints` | `[(x, y), ...]` 嵌套 | `Vec<(i32, i32)>` |

定约：元素一律 **i32 严格 int**（float 拒收，对齐 sf 面既有惯例）；序列
形态宽收（tuple/list/任意可迭代，`vm.extract_elements_with` 一条路径），
固定长度在类型层校验。**Rust tuple 不实现 TryFromObject**（实测）——
点列必须自定义类型，这也是旧"扁平化 + chunks(2) 组对" hack 的根因，
本批连根拔掉。

### 4.3 成形后的 draw 签名（契约源 bridge.rs，探针 sig_probe 锁定）

```python
rect(color, rect, width=0)              # width=0 = 填充（pygame 惯例）
circle(color, center, radius, width=0)
line(color, start, end, width=1)        # width 此前被 Rust 硬编码 1 静默丢弃，本批接通透传
polygon(color, points, width=0)         # points = [(x, y), ...]
fill(color)
```

> 注：line 的 width 现已全程透传，但 starfish v1 的 line 渲染恒 1px
> （`draw.rs` `let _ = width`），加粗随其后续版本落地——已如实注释。

## 五、批次 B：原生 pygame 模块

### 5.1 模块构建与注入

`#[pymodule]` 生成 `module_def(&Context) -> &'static PyModuleDef` +
exec slot。注入 = 多阶段 init 手动驱动：

```rust
let module = def.create_module(vm)?;   // phase 1：dict + methods
def.exec_module(vm, &module)?;         // phase 2：挂嵌套子模块（display/event/time）
sys.modules["pygame"] = module;        // + 三个子模块补进 sys.modules
```

选择 sys.modules 注入而非 builder `add_native_module` 的原因：后者在
builder 期拿不到 Context（module_def 需 ctx intern 名字），而注入点位
本就与旧 shim 装配一致（enter 内、脚本前）。

### 5.2 三个 pyclass

| 类 | payload | 要点 |
|---|---|---|
| `Screen` | 单元结构（真身 = Rust 全局 Screen，宿主壳装配） | `render()` → 开会话 + 返回 Session；`render_depth` → NotImplementedError（v1.1）；`fill` |
| `Session` | 单元结构 | `__enter__`(zelf 透传) / `__exit__`(session_end + False 不吞异常)；五绘制方法 **pymethod 直收 FromArgs 结构体**——kwargs/缺省值与批次 A 完全一致 |
| `Event` | `{typ: PyStrRef, key: PyObjectRef, x, y, button: i32}` | `#[pyattr]` 暴露（match 类模式解构用）；`#[pygetset(name = "type")]` 改名；`with(Representable)` 实现 repr；`from_engine()` 承接引擎事件→对象映射（定约：Escape=27，Other 带原值） |

pymethod 收 FromArgs 结构体的样板：stdlib `_queue.rs` 的
`fn put(&self, args: PutArgs, vm)`——方法与自由函数同一条 bind_for 路径。

**分层坚持**：会话（thread-local RenderPass）、事件队列、诊断计数留在
`bridge.rs`，native_pygame 只做 Python 面——pyclass payload 不持有 GPU 资源，
零 PyRef 借用/重入风险面（批次 B 的风险评估结论：这是无头三端验证刚
打通后最稳的形态）。

### 5.3 pymodule 宏机制备忘（实测踩坑，防重蹈）

1. `pyattr`/`pyfunction`/`pymethod`/`pygetset` 是被 `#[pymodule]` /
   `#[pyclass]` 宏消费的**内部标记**——它们不是宏，root re-export 里
   没有，import 必报 unresolved；真实展开器只有 `pyclass`/`pymodule`
   （属性宏）与 `FromArgs`（derive，需直依赖 `rustpython-derive`）；
2. **子模块必须嵌套声明在父 mod 内，且不带 `(sub)`**——父宏只为嵌套的
   non-sub Item::Mod 生成"create+exec+set_attr"挂载代码；
   `(sub)` 是另一种形态（属性并入父模块，配合 `with()` 使用，如
   `_codecs_windows`），不产生独立子模块；
3. 属性宏在**包含它的作用域**解析——嵌套子模块的 `#[pymodule]` 要在
   父 mod 作用域可见；
4. `with(协议)` 挂在 **impl** 的 `#[pyclass]` 上，不挂在 struct 上；
5. struct 上的 `#[pyclass]` 必须配 `#[pyattr]`（注册进模块）或
   `no_attr`（自由类型）。

## 六、demo（探针）设计

### 6.1 binding_probe：可视化全链路验收

- **壳**（.rs）：宿主四步装配（§2.2）+ 诊断日志四通道
  （println / console_log / 文件 / TCP devlog，300ms 超时 + 一次失败拉黑）；
- **脚本**（.py，include_str! 静态嵌入三平台零文件依赖）：标准 pygame
  写法——生成器门（`yield` = 帧边界）+ `with screen.render() as r:`
  会话绘制。验收面覆盖：
  - 位置参数全形态（3 元色自动补 alpha、嵌套点列）；
  - `r.rect((255,255,255), (x,430,60,60), 4)`——width 生效（白描边矩形）；
  - `r.rect(color=(90,200,255), rect=(x,120,60,60))`——**kwargs 形态**；
- **判定**：生命周期六标记（starting → set_mode OK → genesis → 模块注入
  → generator created → frame loop）+ 帧拍计数 + 零脚本异常 + 干净退出。

### 6.2 sig_probe：无头签名契约锚点（本批新增）

**设计动机**：签名契约要可回归、先于真机跑、不依赖窗口/GPU。21 项
可执行规格：

- **正路径 12 项**（批次 A）：位置/kwargs/缺省值/3 元色/嵌套点列/tuple 点列
  各形态绑定通过；
- **负路径 6 项**（批次 A）：颜色分量不足、越界（中文报错）、float 严格拒、
  缺必填参（MissingRequiredArgument）、点长度错、未知 kwarg；
- **模块路径 9 项**（批次 B）：import、常量同源、Color 三调用形态、
  init 占位、set_mode→Screen、event.get() 无头排空、Event 类暴露、
  get_ticks。

**判定原理**（无头的关键技巧）：绘制调用绑定成功后必然撞
`with_session` 的"会话外"报错（文案固定含"会话内调用"）= 绑定通过；
参数层错误在绑定阶段先拒绝、文案不同——用异常文案区分，零 GPU 即可
验完整个绑定层。`sf_draw_fill`/`screen.render`/`fill` 触碰
`get_screen()`，无头不测（桌面 binding_probe 覆盖）。

**运行**：`cargo run --release -p pygame-rs --example sig_probe`
（debug 亦可——/STACK 修复后 debug 全可用，性能验收仍以 release 为准）。

## 十、批次 C 追记（同日）：Rect + key/mouse

### 10.1 Rect——第一个直通句柄 pyclass

- payload = `Cell<starfish Rect>`：**RP pymethod 无 `&mut self` 形态**
  （内置类型一律内部可变性），Rect 是 Copy 故 `Cell` 即可支撑 `*_ip`
  原地方法；`get()` 访问器转出给 args 层；
- 属性面：`left/top/width/height`（读写）+ `x/y/w/h` 别名（读写）+
  `right/bottom/centerx/centery`（可写计算属性，纯算术）+ `size/topleft/
  center`（tuple 只读 v1）；
- 方法面：move/move_ip/inflate(_ip)/scale_by(_ip)/update/clamp(_ip)/clip/
  contains/collidepoint/colliderect/collidelist(all)/union(_ip)/fit/copy/
  normalize（**差异标注：starfish normalize 返回新 Rect，pygame 是原地**）；
  clipline（starfish stub）与 collidedict（HashMap 参数面）明确出栈；
- **args::SfRect 直通分支**：downcast `PyRect` → 零转换拷贝字段——
  `r.rect(pygame.Rect(...))` 实例直接当 draw 参数（sig_probe 契约锁定）；
- Comparable（值相等）+ Representable（`<Rect(l, t, w, h)>`）+
  Constructor（`(i32,i32,i32,i32)` 元组 Args）。

### 10.2 Key/mouse——typed 键值与查询

- **typed 决策**：引擎（W3C KeyboardEvent.code 命名）**没有 pygame 整数
  键码表**——K_* 用 `Key` pyclass 实例（payload = `KeyCode`，Comparable
  值相等），跟随 starfish locals 既定设计，零发明；108 键 `KEY_TABLE`
  经**父模块用户版 `module_exec`** 注册为 pygame 顶层常量（pyattr 注册
  不了运行时构造的实例；用户 exec 会顶替自动版，需手动补
  `__init_attributes` 挂子模块）；
- `Event.key` 从 int 改为 **Key 实例**——脚本 `e.key == pygame.K_x`
  写法不变成立（Key 值相等）；`K_ESCAPE: i32 = 27` 旧常量删除；
- `key.get_pressed() -> Pressed`（`.get(K_x) -> bool`）；状态由 starfish
  事件泵喂（bridge::pump → event::get 自动驱动，零接线）；
- `mouse.get_pos/get_pressed` 直调 starfish（状态同上）；
- `RESIZABLE/FULLSCREEN/NOFRAME/HIDDEN` 旗标透传（set_mode 前向兼容）。

### 10.3 批次 C 实测备忘

- `#[pymethod]` 参数收 `PyRef<PyKey>`（`&PyKey` 形参不满足
  IntoPyNativeFn）；payload 需满足 Debug（starfish `Pressed` 零尺寸视图
  无 Debug → PyPressed 改零尺寸实时取视图）；
- `usize` → PyObjectRef 无 From（用 `vm.ctx.new_int`）。

### 10.4 批次 C 验证

sig_probe 扩至 **40 项**（+19：Rect 12 / Key 3 / mouse 2 / 旗标 1 /
直通 draw 1），debug + release 全过；wasm32 lib 编译通过；
binding_probe 桌面可视化（Rect 实例直通绘制 + typed K_ESCAPE 事件判断）。

## 十一、批次 D 追记（同日）：font 文字上屏 + 绑定面拆分落地

### 11.4 Android 白闪修复（批次 D 真机反馈）

现象：黑主题生效（启动黑 ✓），但引擎初始化后又白屏 ~1s 才进正常渲染。
根因：pygame 层 Screen 清屏是**透明黑**（设计如此——fill 是覆盖 quad，
消除"首个 fill 走清屏"特例），成品帧不透明；白屏出在 **surface 配置完成
→ 首帧 present 之间**（RP genesis ~1s），swapchain 未初始化 buffer 在部分
设备合成器上显示为白——主题黑只覆盖窗口创建前，管不到这段。

修复（宿主壳定约）：`set_mode` 成功后**立即 `screen.fill(底色)` +
`display::flip()`** present 一帧深色底，把未初始化窗口填掉。已写入
binding_probe.rs 与 CLAUDE.md Android 坑节。

## 十二、批次 E 追记（同日）：pygame.mixer 绑定

### 12.1 starfish 侧接口补充（用户授权，引擎两处小改）

- **`SoundData::from_bytes(Vec<u8>)`**：与 from_file 对称，内部 =
  SymphoniaReader::from_bytes + 解码循环下沉（probe_audio 样板进 base）；
  格式按内容探测（OGG/MP3/FLAC/WAV）；SFX 三平台零落盘；
- **`AudioMixer::music_load_bytes(Vec<u8>)`**：镜像 music_load_file，
  内部 `MusicStream::from_bytes(data, output_sample_rate())`——music 字节
  路径免落盘。

### 12.2 绑定面

- `pygame.mixer.init(channels=8)/quit/get_init/set_master_volume/get_busy`；
- `pygame.mixer.Sound` pyclass：构造三形态（**() 无参 = 内嵌 bleep.wav**
  （Font(None) 惯例延续）/ 路径字符串 / bytes 对象）；方法
  `play(loops=0)/stop/set_volume(0..1)/get_length`；**payload = Arc<SoundData>
  + Cell<Option<usize>> 最近通道**（set_volume/stop 作用于最近通道——
  通道索引停止后回收复用，starfish 通道模型固有限制，文档标注）；
- `pygame.mixer.music` 二级嵌套子模块：`load(path)/load_bytes(bytes)/
  play(loops)/stop/pause/resume/set_volume/get_busy`。

### 12.3 实测坑（批次 E）

1. **RP 原生函数/pymethod 不支持 `&str` 形参**（IntoPyNativeFn 不满足）
   ——统一 `PyStrRef` + `to_str()`；
2. **FromArgs 元组元素恒必填**（`Option<i32>` 元素救不了 0 参调用）——
   可选参数用 `#[derive(FromArgs)]` 结构体 + `#[pyarg(any, optional)]`；
3. **payload 必须 Debug + PyPayload derive**（into_ref 约束）——starfish
   `Pressed` 零尺寸视图无 Debug → 改零尺寸实时取；
4. **混音器 Drop 留到主线程 TLS 析构期会崩**（cpal 流 Drop 与 TLS 竞争
   → STATUS_STACK_BUFFER_OVERRUN）——宿主壳显式收口
   `rpy::bridge::mixer_quit()`（sig_probe/binding_probe 均已加）。

### 12.5 Web 音频手势解锁（批次 H 补，真机反馈；批次 G/H 收尾定型）

浏览器自动播放策略：AudioContext 在首次用户手势前被浏览器暂停
（console 警告 "The AudioContext was not allowed to start"）——音频
静音但应用不崩。**定约（最终形态）：mixer 初始化与提示音播放全部
延后到首次用户手势**（首个 KEYDOWN 时 Sound() 创建 + play——
AudioContext 在手势调用栈内创建即 RUNNING，无暂停无警告）。
桌面/Android 无手势限制即时出声（行为一致：首次交互后音频生效，
Web 游戏标准形态）。

### 12.4 批次 E 验证

sig_probe 扩至 **52 项**（+6：mixer.init/Sound() 内嵌构造/get_length/
play/stop/坏字节 ValueError）；桌面可视化（启动提示音听感 + 468 帧零
异常）；wasm32 编译通过；Android 重打包。已知边界：Web 首次手势前
可能静音（浏览器自动播放策略）。

### 12.5 旧示例退役（批次 E 收尾）

  [[example]] 并恢复 bridge 旧别名面）；

## 十三、批次 F 追记（同日）：Surface 大件（GPU 直通定约）

### 13.1 pygame.Surface pyclass

payload = **owned starfish Surface**（无 Clone/Debug/生命周期参数——
手写 Debug；全 API &self 内部可变性，Python 方法友好）。方法面：
`get_size/fill(color)->Rect/blit(src, dest)->Rect/get_rect`。
构造 = `pygame.Surface((w, h))`——**GPU 需已 init**（构造/使用须在
display init 后，与真 pygame 的差异，文档标注）；self-blit 会 panic
（starfish assert_not_self）。

### 13.2 transform / image

- **transform**：flip_x/flip_y/scale/rotate/rotozoom 全 GPU 采样
  （`&Surface -> Surface`，恒线性平滑）；
- **image**：`load(path)`（桌面）/ `load_from_bytes(bytes)`（Web ✓）/
  `save(surface, path)`（桌面 block_on 专用；格式按扩展名，无扩展名
  默认 PNG）/ `get_extended()`。

### 13.3 Font.render 一等化 + 用户定约

- `Font.render(text, antialias=True, color) -> Surface`：文字表面
  一等化（可 blit / 可 transform）；`Session.text` 快捷融合形态保留；
- **用户定约：GPU 直通优先，CPU 回读后续**——get_at/set_at/tostring
  等回传 CPU 的接口出栈（底层 starfish `readback_rgba` 为 pub(crate)
  async，需协商 pub 包装 + wasm 异步语义）；transform 角度入参用
  `ArgIntoFloat` 兼收 int/float（f32 形参严格拒 int 的既有约束）。

### 13.4 批次 F 验证

sig_probe 扩至 **53 项**（+1 get_extended）；桌面可视化新增**橙色
tile / 旋转 tile / 白字 "Surface!"** 三元素（Surface→transform→blit
全链）；wasm32 编译 + 无头截图实证；Android 重打包。

### 13.5 Surface 生命周期闪烁（批次 F 真机反馈，2026-09-29）

现象：文字与几何图形**交替闪烁**（有时文字、有时几何）。
根因：demo 每帧新建/丢弃 tile/rot/tsurf Surface，而 blit 命令是
**延迟提交**（ADR-5）——纹理在命令真正执行前已随 Surface drop 销毁，
该帧部分绘制丢失；双缓冲交替呈现为内容来回闪。

修复/定约：**静态 Surface 创建一次、循环内复用**（starfish
pygame_probe 同款正确用法；真 pygame 亦然——静态表面不每帧重建）。
后续 starfish 可评估 blit 时对源纹理做存活保活（Arc 化或 flush 时机
前移），从引擎层根治。

## 十四、批次 G 追记（同日）：CJK 字体能力

### 14.1 设计：io 预加载 + 字节缓存 + Font 解析链

`Font::from_bytes` 同步零阻塞。Windows 宿主另预载系统 `msyh.ttc`
（TTC index0 = 微软雅黑常规体，机器必有）。

### 14.2 绑定侧

- `bridge::FONT_CACHE`（thread-local HashMap）+ `font_cache_set/get`；
- `Font` 构造解析链：**缓存名 → bytes 对象 → 磁盘路径（非 wasm）→
  ValueError**；FontError → ValueError（Debug 形态）；
- demo：`Font("cjk", 40)` 尝试 + 失败回退 Antonio（try/except，中文
  缺字静默跳过的既有语义）——三平台零异常运行。

### 14.3 验证与状态

桌面：msyh.ttc 预载 ✓ → Font("cjk") 构造/解析零异常 → 80 帧渲染
（中文上屏待真机/Web 目视）。Web：`web/fonts/cjk.ttf` =
**霞鹜文楷 Lite Regular**（1.18MB，OFL 授权，GitHub 下载）。Android：
CJK 字体文件未部署（Font("cjk") 报错 → demo 回退拉丁，无异常）——
后续如需真机中文，走落盘或资源部署批次。

### 14.4 已知边界

- 卓易通冷启动白色 starting window（容器层，不可控，已接受）；
- CJK 字形缓存无上限（demo 规模无碍）；无字体回退链（单字体；
  回退链需 starfish 侧设计）。

### 13.6 Surface 会话语法（用户提案，同日落地）

用户观察：Screen 与 Surface 本质都是 DrawTarget——离屏表面的
fill/绘制也该用 with 会话（与 Screen 同语法），而非散装方法调用。
落地：`PySurface.render() -> SurfaceSession`（payload 改
`Arc<SfSurface>` 共享；会话对象无状态，方法经 `with_batch` 累积进
Surface 内部单一 batch，`__exit__` flush 打包）。**Surface 内部单一
batch 天然无 Screen 的通道拆分问题**——离屏会话比 Screen 会话更安全。
